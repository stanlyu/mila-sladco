Задача — создать максимально простой, эстетичный и автономный мобильный сайт (Mobile-First Taplink + интерактивная витрина десертов), синхронизированный с облачной базой на GitHub:

## 3. Облачная синхронизация с базой данных (`js/sync-service.js`)

1. **Файлы базы данных и облачные эндпоинты:**
   - Облачная REST-база данных (высокоскоростной endpoint с поддержкой CORS, без авторизационных токенов):
     - Каталог: `https://api.npoint.io/2a6bc08a5699cf1f7910`
     - Профиль шефа и PIN-код: `https://api.npoint.io/1622863e7880b2c4788d`
   - Локальные/GitHub файлы в репозитории: `data/catalog.json`, `data/profile.json` (резервный fallback).
2. **Как работает чтение для покупателей и шефа:**
   - При входе на сайт сначала моментально отрисовывается локальный кэш (0 мс задержки, Offline-First).
   - В фоне `SyncService.pullFromRemote()` проверяет свежие данные через облачный REST API с анти-кэш параметром (`?t=timestamp` + `cache: no-store`).
   - Если данные обновились (с другого устройства или Людой), витрина и профиль мягко перерисовываются автоматически без необходимости сбрасывать кэш браузера.
3. **Как работает запись из кабинета кондитера (Zero-Token UX):**
   - Никаких технических токенов, PAT, настроек репозиториев или кнопок в интерфейсе Люды **нет**!
   - Люда просто входит по своему PIN `1819`, меняет цену, фото, описание или скрывает позицию и нажимает «💾 Сохранить».
   - Изменения мгновенно применяются локально и в фоне отправляются в облачную базу данных.
4. **Синхронизация PIN-кода между устройствами:**
   - Хэш PIN-кода кондитера (`pinHash`) хранится в объекте профиля.
   - При смене PIN на телефоне он автоматически отправляется в базу. На ноутбуке или другом браузере при входе подтягивается актуальный хэш.
5. **Сжатие фотографий на клиенте:**
   - Перед отправкой фото с камеры смартфона (обычно 8-15 МБ) автоматически сжимаются на Canvas до 900px и качества JPEG 82% (~70-120 КБ), что исключает задержки сети и экономит трафик.
